# GRAFT-Net v0.1.0 Design

**Author:** Desenyon
**Date:** 2026-03-09
**Status:** Approved

## Objective

Build a research-first public repository for **Gradient-Routed Predictive Attention Network with Latent Topology Learning (GRAFT-Net v0.1.0)**. The repository should support publishable experimentation across sequence classification, time-series forecasting, and graph prediction, with clean ablations, reproducibility controls, visualization tooling, and separate compute profiles for local and scaled runs.

## Project Direction

The repository will be implemented as a **modular research platform** rather than a one-off experiment bundle. This balances breadth and rigor:

- breadth through support for three benchmark families
- rigor through a shared experiment harness, reproducible configurations, and direct baseline comparisons
- extensibility through reusable model blocks and task adapters

## Core Model Architecture

Each GRAFT-Net block contains three primary modules plus residual and normalization structure.

### 1. Predictive Attention

The block first predicts a short-horizon latent state from the current hidden representation:

- input: `h in R^(B x N x d)`
- predictor: `h_future = f_predict(h)`
- attention logits: computed from `h_future`
- values: projected from the current `h`

This preserves the central research hypothesis: attention is allocated based on anticipated future representation structure rather than current structure.

Expected design characteristics:

- configurable predictor depth and bottleneck size
- optional stop-gradient target matching against later hidden states
- compatibility with full attention and masked attention depending on task

### 2. Latent Topology Learning

The block learns a sparse directed latent graph over tokens:

- pairwise edge scoring from token-pair features
- soft adjacency for regularization and diagnostics
- top-k sparsified adjacency for message passing
- graph message aggregation projected back into model dimension

The graph output is fused with predictive-attention output using a gated residual merge so the model can choose when latent relational structure should dominate.

Expected design characteristics:

- configurable edge scorer
- node-local top-k sparsification
- diagnostics for graph density, entropy, and per-node connectivity
- visualization hooks for learned topologies

### 3. Gradient-Routed Experts

After attention and topology fusion, the block applies an MoE-style expert stage routed by predicted learning utility:

- router predicts per-expert utility scores for each token
- top-k experts are selected from predicted utility
- selected experts process the token
- outputs are combined using normalized utility-derived weights

During training, the utility predictor is supervised against gradient-derived targets computed from expert contributions. During inference, routing uses only the learned predictor.

Expected design characteristics:

- stable auxiliary routing targets
- expert load-balancing regularization
- routing traces for specialization analysis
- ablation path to standard similarity-based or dense FFN baselines

### 4. Block Composition

Each model block follows this logical sequence:

1. normalize current hidden state
2. predict future latent state
3. compute predictive attention
4. infer latent topology and perform message passing
5. fuse attention and topology outputs
6. route through gradient-utility experts
7. apply residual updates and normalization

Each module must be individually disableable for ablation:

- `predictive_attention`
- `latent_topology`
- `gradient_routing`

This ensures module-drop ablations use the same codepath and trainer.

## Repository Architecture

The repository should be organized as a research library with a shared experiment system.

### Source Layout

`src/graft_net/`

- `models/`: assembled model definitions and baseline variants
- `modules/`: predictive attention, latent topology, fusion, expert blocks
- `routing/`: utility prediction, routing policies, load balancing
- `topology/`: edge scoring, sparsification, graph message passing
- `losses/`: future-state, topology, routing, and task losses
- `tasks/`: task heads and task-specific adapters
- `data/`: dataset wrappers, preprocessing, and datamodules
- `train/`: training loops, evaluation, checkpointing
- `eval/`: benchmark runners, ablation utilities, metric aggregation
- `viz/`: plotting and artifact rendering
- `utils/`: config, seeding, device, logging, registry helpers

### Supporting Layout

- `configs/`: hierarchical experiment configs
- `scripts/`: command-line entrypoints
- `tests/`: unit, integration, and smoke tests
- `docs/`: architecture notes, reproducibility guides, benchmark docs
- `artifacts/` or `outputs/`: generated run outputs

## Benchmark Families

Version `v0.1.0` will include all three requested benchmark families:

### 1. Sequence Classification

Primary stable benchmark family used to validate classification behavior, convergence, and routing specialization.

### 2. Time-Series Forecasting

Primary stable benchmark family used to test predictive reasoning and horizon-sensitive representation quality.

### 3. Graph Prediction

Included in `v0.1.0` as an experimental track. This enables early relational evaluation while honestly signaling lower maturity if results lag the other two tracks.

## Baselines

All baselines should run under the same data, training, and evaluation harness:

- standard transformer
- MoE transformer
- graph-aware transformer or graph transformer baseline

This is required for defensible comparison and publishable ablations.

## Training Design

Training will be end-to-end with mixed precision support and reproducibility controls.

### Optimizer and Schedule

- optimizer: `AdamW`
- learning rate schedule: warmup plus cosine decay
- gradient clipping enabled
- seed control and deterministic toggles where feasible
- local and scaled config profiles

### Loss Stack

Total loss:

`L_total = L_task + lambda_future * L_future_prediction + lambda_grad * L_gradient_prediction + lambda_topology * L_topology + lambda_balance * L_load_balance`

#### `L_task`

Primary task objective:

- classification cross-entropy
- forecasting regression loss
- graph task objective depending on benchmark

#### `L_future_prediction`

Supervises future-state predictions against later-layer or projected target states to ground predictive attention.

#### `L_gradient_prediction`

Supervises the utility router against gradient-derived usefulness targets during training.

#### `L_topology`

Encourages sparsity, discourages degenerate graphs, and can optionally enforce consistency constraints.

#### `L_load_balance`

Prevents expert collapse and encourages meaningful utilization.

## Configuration Strategy

Configurations must support both local and scaled execution:

- `configs/compute/local/`: small batch sizes, reduced model sizes, smoke datasets
- `configs/compute/scale/`: larger batch sizes, stronger models, paper-grade settings

Other config groups:

- `model/`
- `task/`
- `data/`
- `trainer/`
- `benchmark/`
- `ablation/`
- `baseline/`

All experiment commands should be reproducible from checked-in configs.

## Visualization And Diagnostics

The repository must generate visual artifacts directly from experiment outputs:

- training and validation curves
- learned latent topology graphs
- expert routing heatmaps and specialization summaries
- predicted vs true gradient utility plots
- ablation comparison charts

Diagnostics should be part of the normal experiment workflow, not post hoc notebook-only analysis.

## QA And Validation Strategy

Research-grade quality requires built-in verification.

### Unit Tests

- tensor shape contracts
- masking logic
- topology sparsification correctness
- routing top-k behavior
- loss target construction

### Integration Tests

- one training step executes
- one evaluation step executes
- checkpoint save/load roundtrip works
- ablation toggles preserve model execution

### Smoke Tests

- local config runs on each benchmark family
- baseline config runs under shared harness
- figure generation consumes logged artifacts correctly

## Research Claims To Test

The repository should explicitly test these three hypotheses:

1. predicting future representations improves attention quality
2. routing by predicted gradient usefulness improves learning efficiency
3. learning latent topology improves relational reasoning

Each claim must be tied to direct ablations and measurements rather than only end-task metrics.

## Release Scope For v0.1.0

`v0.1.0` should ship with:

- full modular model implementation
- baseline implementations under the same trainer
- training and evaluation scripts
- ablation runners
- visualization generation
- reproducibility documentation
- separate local and scaled experiment profiles

The graph benchmark track may be labeled experimental if its empirical maturity is behind the sequence and time-series tracks.
