## 1. Executive Summary

GRAFT-Net is a **research-grade PyTorch repository** implementing a novel neural network block that combines three mechanisms:

1. **Predictive Attention** — attention queries derived from predicted future latent states
2. **Latent Topology Learning** — dynamic sparse relational graph over tokens
3. **Gradient-Routed Experts** — top-k MoE routing supervised by gradient utility signals

The goal is a **publishable, reproducible experimental platform** with defensible baselines, strict ablations, integrated visualization, and CI-enforced quality across three benchmark families: sequence classification, time-series forecasting, and graph prediction (experimental).

This plan consolidates the existing design doc and implementation plan into a single self-contained execution document enriched with:

- Architecture Decision Records (ADRs) for all major choices
- TDD red-green-refactor sequence for every module
- CI/CD pipeline specification (GitHub Actions)
- MLflow experiment tracking integration
- Hypothesis-driven ablation experiment design (ICE-scored)
- Observability strategy for training runs
- Security and dependency management policy
- Release and changelog process

## 2. Research Hypotheses (Experiment Designer)

Each hypothesis follows the **If/Then/Because** format with a defined primary metric and ICE score.

| ID  | Hypothesis | Primary Metric | ICE Score |
|-----|-----------|---------------|-----------|
| H1  | If attention uses predicted future state queries, then sequence classification accuracy will improve by ≥1% vs standard transformer baseline, because future-grounded queries reduce cross-entropy on tokens that matter later | Val Accuracy | 8.4 |
| H2  | If experts are routed by predicted gradient utility, then training converges in fewer steps (≥10% faster) than standard MoE routing, because useful experts receive gradient signal more consistently | Steps to 95% best val loss | 7.2 |
| H3  | If the model learns a latent topology over tokens, then forecasting MAE will improve by ≥3% vs graph-transformer baseline without explicit edges, because relational structure discovered from data generalises better | Forecast MAE | 7.8 |

**Ablation matrix required to test each hypothesis:**

| Ablation Config | H1 | H2 | H3 |
|----------------|----|----|-----|
| `full_model` | ✓ | ✓ | ✓ |
| `no_predictive_attention` | control | ✓ | ✓ |
| `no_gradient_routing` | ✓ | control | ✓ |
| `no_latent_topology` | ✓ | ✓ | control |
| `no_topology_no_routing` | ✓ | — | — |
| `standard_transformer` | — | — | baseline |
| `moe_transformer` | — | baseline | — |
| `graph_transformer` | — | — | baseline |

**Guardrail metrics (must not degrade):** GPU memory per batch, throughput (examples/sec), training stability (no divergence in first 100 steps).

## 3. Architecture Decisions (ADRs — Senior Architect / CTO Advisor)

### ADR-001: Modular Source Package Over Notebook-Centric Research

**Status:** Accepted  
**Context:** Research repos often start in Jupyter notebooks, creating reproducibility debt.  
**Decision:** All production logic lives in `src/graft_net/` with explicit public API. Notebooks are diagnostics-only and depend on the package.  
**Consequences:** Clean imports, testable modules, importable by CLI scripts.

### ADR-002: Hydra for Hierarchical Configuration

**Status:** Accepted  
**Context:** Experiment configs need to compose model, compute, task, and ablation dimensions independently.  
**Decision:** Hydra + OmegaConf with config groups for `model/`, `compute/`, `task/`, `data/`, `ablation/`, `baseline/`.  
**Consequences:** Reproducible CLI commands, structured override sweeps.

### ADR-003: MLflow for Experiment Tracking

**Status:** Accepted  
**Context:** Need to compare ablation runs and plot training curves for publication.  
**Decision:** MLflow (local file-system backend for v0.1.0, upgradeable to remote). All metrics, params, and artifacts logged per run. Runs tagged with git commit hash.  
**Consequences:** Reproducibility for every result in the paper, artifact diffing between runs.

### ADR-004: Typed Output Dataclasses on Every Module

**Status:** Accepted  
**Context:** Modules need to pass diagnostics to losses and visualization without coupling through positional returns.  
**Decision:** Every module (attention, topology, experts, block, backbone) returns a frozen dataclass with named fields.  
**Consequences:** Explicit contracts, easy selective logging, resistant to refactoring bugs.

### ADR-005: PyTorch AMP for Mixed Precision via Context Manager

**Status:** Accepted  
**Context:** Local smoke runs need to be feasible on CPU; scale runs target GPU.  
**Decision:** `torch.amp.autocast` context managed by trainer, disabled on CPU.  
**Consequences:** Single code path for local and scale.

### ADR-006: Module-Drop Ablation at Config Level Not Code Level

**Status:** Accepted  
**Context:** Ablations must use the same code path as full runs.  
**Decision:** Each novel module checks `cfg.use_*` flag and routes to an identity/bypass sub-path within the module itself. No conditional imports.  
**Consequences:** True apples-to-apples ablation.

## 6. Implementation Roadmap

Tasks are ordered by dependency. Each task follows **strict TDD (red → green → refactor)**.

### Phase 1 — Foundation

#### Task 1: Bootstrap Research Repository

**Deliverables:** `pyproject.toml`, `src/graft_net/__init__.py`, `src/graft_net/version.py`, `tests/test_package_metadata.py`, `README.md`, `.gitignore`, `.env.example`

**Failing test first:**
```python
from graft_net import __version__
def test_package_exposes_version() -> None:
    assert __version__ == "0.1.0"
```

**pyproject.toml** runtime deps: `torch>=2.2`, `hydra-core>=1.3`, `omegaconf>=2.3`, `torchmetrics>=1.3`, `einops>=0.7`, `matplotlib>=3.8`, `seaborn>=0.13`, `networkx>=3.2`, `mlflow>=2.11`  
**pyproject.toml** dev deps: `pytest>=8`, `pytest-cov`, `ruff>=0.3`, `mypy>=1.9`, `pip-tools`

#### Task 2: Configuration and CLI Skeleton

**Deliverables:** All `configs/` files, `scripts/train.py`, `scripts/evaluate.py`, `src/graft_net/utils/config.py`

**Key test:** Hydra compose loads default config with `model.name == "graft_net"` and `compute.profile == "local"`.

#### Task 3: Tensor Utilities and Model Config Objects

**Deliverables:** `src/graft_net/utils/tensor.py`, `src/graft_net/models/config.py`

**`GraftNetConfig` fields:**
- `embed_dim: int = 256`
- `num_heads: int = 8`
- `num_layers: int = 4`
- `num_experts: int = 8`
- `experts_topk: int = 2`
- `expert_hidden_dim: int = 512`
- `predictor_hidden_dim: int = 128`
- `topology_topk: int = 4`
- `use_predictive_attention: bool = True`
- `use_latent_topology: bool = True`
- `use_gradient_routing: bool = True`
- `dropout: float = 0.1`
- `max_seq_len: int = 512`

### Phase 2 — Core Model

#### Task 4: Predictive Attention Module

**Deliverables:** `src/graft_net/modules/predictive_attention.py`

**Output dataclass:** `PredictiveAttentionOutput(attended, future_state, attention_weights)`

**Ablation path:** when `use_predictive_attention=False`, queries derive from current state (standard attention), `future_state` is identity.

#### Task 5: Latent Topology Learning

**Deliverables:** `src/graft_net/topology/edge_scorer.py`, `src/graft_net/topology/sparsify.py`, `src/graft_net/topology/message_passing.py`, `src/graft_net/modules/latent_topology.py`

**Output dataclass:** `TopologyOutput(graph_state, soft_adjacency, hard_adjacency, graph_entropy, mean_degree)`

**Ablation path:** when `use_latent_topology=False`, `graph_state` is zeros, adjacency is identity.

#### Task 6: Gradient-Routed Experts

**Deliverables:** `src/graft_net/routing/gradient_router.py`, `src/graft_net/modules/experts.py`

**Output dataclass:** `ExpertOutput(output, routing_scores, selected_experts, expert_load)`

**Ablation path:** when `use_gradient_routing=False`, falls back to dense FFN.

#### Task 7: GRAFT Block and Backbone

**Deliverables:** `src/graft_net/models/block.py`, `src/graft_net/models/backbone.py`, `src/graft_net/models/heads.py`

**Block output dataclass:** `BlockOutput(hidden, attn_out, topo_out, expert_out)` carrying all sub-module outputs for loss construction and logging.

### Phase 3 — Training Infrastructure

#### Task 8: Losses and Training Targets

**Deliverables:** All `src/graft_net/losses/*.py`

**Total loss formula:**
```
L_total = L_task
        + λ_future  * L_future_prediction
        + λ_grad    * L_gradient_prediction
        + λ_topology* L_topology
        + λ_balance * L_load_balance
```

Default λ values in config: `0.1, 0.05, 0.01, 0.01`.

#### Task 13: Trainer, Evaluator, and Checkpointing

**Deliverables:** `src/graft_net/train/trainer.py`, `src/graft_net/eval/evaluator.py`, `src/graft_net/train/checkpointing.py`

**Trainer features:**
- AdamW + cosine schedule with warmup
- Gradient clipping (max norm 1.0)
- AMP autocast (disabled for CPU)
- MLflow run context: logs all loss components, LR, grad norm, throughput per step
- Git commit hash tag on every MLflow run
- `Trainer.for_smoke_test()` factory for integration test use

### Phase 4 — Baselines and Benchmarks

#### Task 9: Baseline Models

**Deliverables:** `src/graft_net/models/baselines/*.py`, `src/graft_net/models/registry.py`

All four models (`graft_net`, `transformer`, `moe_transformer`, `graph_transformer`) registered and returnable from `build_model(name, ...)`.

#### Tasks 10–12: Three Benchmark Tasks

**Task 10 — Sequence Classification:**  
`SequenceClassificationModel(embed_dim, num_layers, num_heads, num_classes)` → `{logits, task_loss}`

**Task 11 — Time-Series Forecasting:**  
`TimeSeriesForecastingModel(embed_dim, num_layers, num_heads, horizon)` → `{predictions, task_loss}`

**Task 12 — Graph Prediction (Experimental):**  
`GraphPredictionModel(embed_dim, num_layers, num_heads, num_classes)` → `{logits, task_loss}`  
All graph-prediction configs labeled `status: experimental`.

### Phase 5 — Diagnostics and Analysis

#### Task 14: Visualization

**Deliverables:** All `src/graft_net/viz/*.py`, `scripts/generate_figures.py`

**Figure types:**
1. Training/validation loss curves (all runs overlaid by config label)
2. Learned topology graph at best checkpoint (networkx + matplotlib)
3. Expert routing heatmap (token × expert utilization)
4. Predicted vs true gradient utility scatter
5. Ablation comparison bar chart (per-hypothesis)

All figures saved as `.pdf` (publication) and `.png` (README preview).

#### Task 15: Ablation and Benchmark Runners

**Deliverables:** Ablation configs, `scripts/run_ablation.py`, `scripts/run_benchmarks.py`

`run_ablation.py` iterates the ablation matrix for H1/H2/H3, logs all runs to the same MLflow experiment, produces comparison CSV.

### Phase 6 — Operations

#### Task 16: Reproducibility and Smoke Verification

**Deliverables:** `README.md` quickstart, `docs/reproducibility.md`, `tests/integration/test_end_to_end_smoke.py`

Full smoke pipeline per task runs in < 60 s on CPU (local config).

## 7. TDD Strategy (TDD Guide)

**Red-Green-Refactor discipline:**
- Every module starts with a failing test that specifies shape contracts, ablation behavior, and edge cases.
- Tests run with `pytest -x` (stop at first failure) during development.
- Coverage target: **≥ 85%** on `src/graft_net/` before any release.
- Coverage measured with `pytest --cov=graft_net --cov-report=term-missing`.

**Test categories:**

| Category | What It Tests | Target |
|----------|--------------|--------|
| Unit | Tensor shapes, masking logic, routing k, sparsification | Per-module file |
| Integration | One forward pass, one training step, checkpoint round-trip | `tests/train/` |
| Smoke | Local config runs end-to-end on each task | `tests/integration/` |
| Config | Hydra config loads, ablation flags flip correctly | `tests/test_config_loading.py` |

## 10. Observability Strategy (Observability Designer)

For training runs, monitoring follows the **USE method** adapted to ML:

| Signal | What | Alert Threshold |
|--------|------|----------------|
| Utilization | GPU util % | < 60% sustained → config issue |
| Saturation | Gradient norm | > 10.0 → clipping failure |
| Errors | NaN loss | Any → stop run immediately |
| Throughput | examples/sec | < 50% baseline → compute regression |
| Topology health | Mean graph degree | < 0.5 → topology collapse |
| Expert load balance | Coefficient of variation | > 1.5 → expert collapse |

**Structured log format** (JSON per step):
```json
{
  "step": 100,
  "train/total_loss": 1.234,
  "train/task_loss": 0.987,
  "train/future_loss": 0.123,
  "train/grad_norm": 0.456,
  "train/throughput_ex_per_sec": 128,
  "topology/mean_degree": 2.3,
  "routing/load_cv": 0.4
}
```

## 11. Performance Profiling Plan (Performance Profiler)

**Profiling checkpoints:**
1. After Task 7 (block assembled): profile single forward pass with `torch.profiler`
2. After Task 13 (trainer): profile full training step (forward + backward)
3. Before scale config is used: verify memory budget fits GPU

**Tools:** `torch.profiler.profile()` with `on_trace_ready=torch.profiler.tensorboard_trace_handler()`, `py-spy` for Python-level hotspots.

**Target (local smoke, CPU, batch=2, seq=16, embed=32):**
- Forward pass < 10 ms
- Peak memory < 500 MB on CPU

**Target (scale, single A100, batch=64, seq=512, embed=256, 4 layers):**
- Throughput > 500 examples/sec

## 14. Reproducibility Contract

A v0.1.0 result is reproducible if the following commands produce matching metrics (within floating-point tolerance):

```bash
# 1. Clone and install
git clone <repo> && cd graft-net
pip install -e ".[dev]"

# 2. Run smoke suite
pytest -v tests/

# 3. Train local sequence classification
python scripts/train.py compute=local task=sequence_classification seed=42

# 4. Train local time-series forecasting
python scripts/train.py compute=local task=time_series_forecasting seed=42

# 5. Run ablation for H1
python scripts/run_ablation.py compute=local hypothesis=H1 seed=42

# 6. Generate figures
python scripts/generate_figures.py --run-id <mlflow_run_id> --output-dir outputs/figures/
```

All commands above must work on a fresh environment with no GPU.

## 15. Open Issues and Risks

| Risk | Severity | Mitigation |
|------|---------|-----------|
| Gradient utility target computation adds 20-30% training overhead | High | Profile after Task 6; make target computation optional via config flag |
| Latent topology memory O(N²) for long sequences | Medium | Cap sequence length in local config; add linear-attention option in future version |
| Expert routing instability early in training | Medium | Warm-start routing with random policy for first N steps; use load-balance loss from step 1 |
| Graph benchmark track empirical maturity | Low | Label as experimental; evaluate after sequence and time-series are validated |
